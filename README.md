# HIBI — 日々の家計

Tauri 2 + React + TypeScript + SQLite の個人用家計簿です。生活費・税金などの特別支出・資産形成を分け、生活そのものの黒字・赤字を確認できます。

## v0.9.0 の追加機能

- **AI分析プロンプトの期間選択**：「月ごと」「四半期」「年間」「任意の期間」を選べます。年間は1〜12月、四半期は1〜3月・4〜6月・7〜9月・10〜12月です。任意期間は開始日と終了日の両端を含みます。
- 比較は前月・前四半期・前年に切り替わります。任意期間では直前の同じ日数を比較します。画面と生成本文に、対象・比較それぞれの日付範囲を表示します。
- 期間全体の収支とカテゴリ別集計に加えて、月別収支を含めます。月別収支は選択範囲内の分析対象記録がある月のみ表示し、未登録月を支出なしとは扱いません。日数の差や途中期間、仮入力の見込みについての注意も依頼文に含めます。

## v0.8.0 の追加機能

- **AI分析プロンプト**：対象月、前月比較、仮入力の見込み、追加の相談内容を選び、AIに貼り付ける依頼文を生成できます。通常支出・特別支出・投資貯蓄、生活収支・現金収支を分けます。
- 標準は収支とカテゴリ別の集計です。明細・メモ・支払い受取方法名は任意で追加できます。生成した本文を確認して「プロンプトをコピー」し、利用するAIに貼り付けてください。条件変更で本文も更新されます。
- 確定分・仮入力・見込みと、未来日付の確定分を区別します。月の途中や未入力の可能性を明記し、給料日前のマイナスや投資への資金移動を生活費の赤字と混同しないよう依頼文に含めます。
- 生成は端末内で行い、AIへの自動送信やAPIキーの設定はありません。コピーした本文を外部のAIへ送信すると、その内容が共有されます。自動コピーが使えない環境では本文を選択し、Ctrl+Cでコピーできます。

## v0.7.0 の追加機能

- **カテゴリ管理 / 設定 → 支払い方法**：一覧の「並び替え」を押し、上下ボタンで順序を変更できます。「並び替えを完了」で通常表示に戻ります。
- 順序は操作ごとに端末内へ自動保存され、収支・定期収支・テンプレートの入力と履歴の絞り込みにも反映します。再起動後も保持します。
- 初回更新時は従来の順序を維持します。名称変更でも順序を維持し、追加項目は末尾に置きます。支払い方法の初期選択は並び順とは別に保持します。

## v0.6.1 の修正

- 定期収支の予定日を変更すると旧日付と新日付で仮入力が重複する不具合を修正しました。同じ周期の変更では、同じ月（毎週は同じ週、毎年は同じ年）の記録を引き継ぎます。
- 未編集の仮入力は新しい予定日に移し、個別に変更した内容・確定済み・スキップ済みの期間は保持します。土日・祝日の調整で月をまたぐ場合も、調整前の予定月で重複を判定します。

## v0.6.0 の追加機能

- **設定 → 祝日**：「祝日を取得・更新」で[内閣府の公式CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)をダウンロードし、端末内のSQLiteに登録します。年別の祝日・休日一覧、収録期間、最終取得日時を表示します。出典：[内閣府「国民の祝日について」](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)。
- **連休を避ける日付調整**：定期設定の前倒し・後ろ倒しは、土日と保存済みの祝日を連続して避けます。CSVに含まれる振替休日・祝日に挟まれた休日も対象です。金融機関や会社独自の休業日は含みません。
- 取得はボタンを押したときだけ行います。取引データやメモは送信しません。取得済みの祝日はオフラインでも利用できます。通信失敗・形式不正・収録期間が短くなった場合は保存済みのカレンダーを維持します。未取得・収録期間外の年は画面に案内を表示します。
- 祝日更新時は未編集の仮入力だけを再計算し、確定済みと個別編集済みの記録を保持します。過去の取引日も変更せずに維持したい場合は、先に確定してください。

- **休日の予定日調整**：「定期収支 → 繰り返し設定」の追加・編集画面で、「変更しない」「土日・登録祝日を避けて前倒し」「土日・登録祝日を避けて後ろ倒し」を選べます。給与・引き落としなど、それぞれの設定で指定します。
- 繰り返し周期と開始日・終了日は調整前の日付を基準にします。月末日を補正したあと、土日の調整を適用します。月や年をまたいだ場合、調整後の日付の月に表示・集計し、一覧には元の予定日も併記します。
- 土日の扱いを変更すると、作成済みの未編集の仮入力も更新します。確定済み・個別に修正済みの記録は保持します。同じ予定の二重登録は発生しません。既存の定期設定の初期値は「変更しない」です。

- **月ごとの定期収支画面**：ダッシュボードには選択月の仮入力・確定済み件数と「月ごとの定期収支を開く」ボタンを表示します。一覧は専用の「定期収支」画面にまとめ、前月・翌月・年月指定で切り替えられます。
- 「月ごとの収支」では取引日の月ごとに仮入力と確定済みを確認・編集できます。金額や繰り返し周期の設定は「繰り返し設定」にまとめています。取引日を別の月に変更した記録は、変更先の月に表示されます。

- **設定 → 支払い方法**：現金・カード・交通系ICなどを追加、名称変更、削除できます。「新しい記録で最初に選択する」を指定すると、新規入力時の初期値になります。収入では受取方法として利用します。履歴にも表示し、支払い方法で検索できます。
- **入力テンプレート**：例えば「通勤電車・片道 230円」の名前・金額・カテゴリ・支払い方法を保存します。ダッシュボードの「いつもの入力」から選ぶと、今日の日付で入力画面が開きます。その回だけ往復分などに金額を変更してから記録できます。
- **定期収支**：給与・家賃などの予定額を、毎週・毎月・毎年で設定します。開始日を基準に繰り返し、該当日がない月は月末に調整します（1月31日→2月28日→3月31日）。終了日・表示の停止にも対応します。
- **仮入力と確定**：日付と確定状態を別に保存します。将来の日付も確定でき、その取引日の月に集計します。通常の新規入力は「確定」が初期値で、手動の仮入力も可能です。
- 定期収支は**仮入力として自動で用意**します。開始日から翌月末までの未処理分が対象です。開始日がそれより先の場合も初回を用意します。起動・再表示時と、入力画面を閉じている間の1分ごとの更新で補充します。アプリを閉じている間の分も次の起動時に補充します。
- 仮入力は定期収支・履歴から編集できます。ダッシュボードからは選択中の月の定期収支画面へ移動できます。「仮入力を保存」で金額・日付の修正だけを保存し、「変更して確定」で同じ記録を確定します。確定時に別の記録は作りません。
- ダッシュボードは**確定分**を主表示とし、その月の「仮入力を含む見込み」を別枠で表示します。履歴は状態でも絞り込め、表示中の合計が仮入力を含むか明記します。月別集計では確定分と見込みを切り替えられます。見込みは作成済みの仮入力だけが対象で、未入力の将来分を含む年間予測ではありません。
- 二重登録を防ぐため、同じ定期設定・予定日の組み合わせは一度だけ処理します。記録を削除しても、その予定は再表示しません。「今回をスキップ」した分を後で記録する場合は、通常の収支登録を使用してください。
- 停止中は新しい仮入力を作りません。作成済み分は残り、再開すると未処理の過去分も補充します。定期設定の金額などを変更すると、個別に編集していない仮入力にも反映します。個別に編集した仮入力と確定分は保持します。同じ周期で予定日を変更すると、同じ期間の仮入力を引き継ぎます。周期の変更や、新しい開始日・終了日の範囲外にある作成済み分は履歴で調整してください。定期設定を削除しても作成済みの仮入力・確定分は残ります。

既存のデータは初回起動時に自動で更新します。v0.1.0 / v0.2.0の登録済み収支は「確定」として、v0.3.0以降の収支は仮入力・確定の状態も含めて保持します。既存の定期設定の日付は変更しません。保存場所とアプリ識別子は同じです。更新したデータはv0.7.0以降で扱ってください。

## 起動

ビルド済みの最新版は **`release/HIBI-0.9.0.exe`** をダブルクリックすると起動します。旧版が開いている場合は、先に終了してください。インストールして使う場合は `release/HIBI-setup.exe` を実行してください。旧版が起動中で`release/HIBI.exe`を更新できない場合も、バージョン付きファイルに最新版を用意します。

この作業フォルダでは、次のコマンドで起動できます。フォルダ内に用意したNode.jsも自動的に検出します。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

通常の開発環境では次を実行してください。

```powershell
npm ci
npm run tauri dev
```

必要な環境：Node.js 22.12以降、Rust MSVCツールチェーン、Microsoft C++ Build Tools、WebView2 Runtime。
Windowsの前提環境は[Tauri公式ドキュメント](https://v2.tauri.app/start/prerequisites/)を参照してください。

`npm run dev` はフロントエンドだけを起動します。ブラウザ単体ではSQLiteに接続できず、起動案内が表示されます。実際の記録には必ずTauriアプリを使ってください。

## 機能

- ダッシュボード：月の収入・通常支出・生活収支・特別支出・投資貯蓄額・現金収支、当年の今日までの年間累計、6か月の推移、通常支出のカテゴリ別内訳。
- 収支登録：日付、整数円の金額、収入・支出、カテゴリ、メモ、3種類の支出。全角数字やカンマ付き金額にも対応。`Ctrl+N`で登録画面を開き、「続けて入力」で日付・カテゴリ・種類を維持。
- 履歴：開始日・終了日、収入・支出、カテゴリ、支出の種類、メモによる検索。編集、確認付き削除、20件ずつのページ表示。
- 月別集計：年の切り替え、12か月の比較、年間合計、月からダッシュボードへの移動。
- カテゴリ管理：追加・名称変更・削除。同名の重複を防止。削除したカテゴリの記録は「未分類」になり、金額と支出種別を維持。
- 空の家計簿から開始。架空の取引やサンプルデータは追加しません。

## 計算の定義

| 指標 | 計算 |
| --- | --- |
| 生活収支 | 収入 − 通常支出 |
| 現金収支 | 生活収支 − 税金・特別支出 − 投資・貯蓄 |
| ダッシュボードの年間累計 | 当年1月1日から今日までの確定分。未来日は除外 |
| 月別集計の年間合計 | 選択年・選択した集計対象の記録。未来日も含む |

例えば、収入250,000円、通常支出200,000円、税金20,000円、証券口座への入金65,000円なら、生活収支は **+50,000円**、現金収支は **−35,000円** です。生活費が赤字になったとは判定しません。

「現金収支」は登録された入出金の差額で、銀行残高や総資産ではありません。投資・貯蓄は家計で使う現金から外へ移した金額として記録します。月の主指標は選択した月の確定分を対象とします。金額は1〜999,999,999円の整数、メモは500文字以内です。

## データ保存・バックアップ

Rust側のTauriコマンドが`rusqlite`でSQLiteを操作します。SQLite本体はアプリに同梱されるため、別途インストールする必要はありません。[Tauri公式のコマンド方式](https://v2.tauri.app/develop/calling-rust/)を使用しています。

- 保存先：アプリ専用のデータフォルダ内の `kakeibo.sqlite3`。
- Windowsでは通常 `%APPDATA%\jp.hibi.kakeibo\kakeibo.sqlite3`。アプリ左下の「この端末だけに保存」で実際の保存先を確認できます。
- データは起動フォルダと分けて保存され、終了・再起動後も保持します。
- 外部通信は祝日更新時の内閣府CSVのHTTPS取得だけです。銀行や証券会社との連携、テレメトリ、外部フォント・画像の読み込みはありません。CSVの応答サイズと待ち時間に上限を設け、取得・検証後にカレンダーと仮入力を一括更新します。
- 外部キー、CHECK制約、パラメータ化SQL、トランザクションによる初期化、スキーマバージョン管理、WALと同期書き込みを使用します。
- バックアップ・復元はアプリを終了してから行ってください。`kakeibo.sqlite3`と同じフォルダにある`-wal`・`-shm`ファイルを取りこぼさないよう、保存先フォルダ全体をコピーします。
- ローカルSQLiteファイル自体は暗号化していません。
- 支払い方法を削除しても、収支とテンプレートは残り、支払い方法だけが「未設定」になります。テンプレートや定期設定の削除でも過去の収支は残ります。
- 支払い方法は支出の分類用で、カード請求・口座残高の管理機能ではありません。カード利用を支出として記録する場合、後日の引き落としをもう一度支出として記録しない運用を想定しています。

## ビルド・検証

祝日の画面テストでは実際に内閣府へ接続するため、インターネット接続が必要です。Rustの祝日テストは取得済みの `tests/fixtures/syukujitsu.csv`（2026-09-12取得、内閣府のShift_JIS CSV）を使い、通信せずに文字コード・連休・保存を検証します。

```powershell
npm run build
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri build -- --debug --no-bundle
npm run test:ui
npm run tauri build
```

`scripts/dev.ps1 -Task build`は配布用ビルド、`-Task test`は集計とSQLiteのテストを実行します。

Windows配布用実行ファイルは `src-tauri/target/release/hibi-kakeibo.exe`、インストーラは `src-tauri/target/release/bundle/nsis/` に生成されます。

画面テストはWindows上の実際のTauriアプリにPlaywrightを接続し、記録・編集・削除・検索・カテゴリ管理・月別集計とプロセス再起動後の保存を検証します。非表示WebViewの描画待機を避けるため、ボタンやラジオの操作にはDOMイベントを使用します。バックエンドのモックは使用しません。事前に上記のデバッグビルドが必要です。テストは `test-results/desktop-data-*` のSQLiteを使い、普段の家計簿には触れません。デバッグビルド限定の`HIBI_TEST_DATA_DIR`とWebView2のデバッグポート19224を使用します。画面の画像は`test-results/`に保存します。
